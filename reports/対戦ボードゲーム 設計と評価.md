# 対戦ボードゲーム 設計と評価

試作前の設計と評価の仮説をまとめた。現在のルールと実行方法は[ボードゲームのREADME](../templates/boardgame/README.md)に記載する。

最初のファクトリーには、**2人が少数の公開枠を先取りし、どの枠を特に欲しいかだけが手札で伏せられるゲーム**を推す。自分が得点する手と、相手の狙いを読んで先回りする手の価値が入れ替わる局面を狙う。初期手札は双方が同じ候補から秘密裏に選ぶ。対戦ごとの変化が足りなければ、初期配置に小幅な乱数を加え、最初の判断前に双方に公開する。AIには自席から見える情報だけを渡し、難度は探索量や相手を読む方策で調整する。評価機には、試合の成立、定石や運への偏り、相手の行動を見て判断が変わった局面を記録させる。人がその局面を駆け引きとして楽しめるかは試遊で確かめる。

## 公開枠と伏せた依頼だけで、選ぶ手が逆転する

独自の試作候補「灯台群」では、二人が公開の航路3枠から交互に一つずつ担当する。同じラウンドの航路は一度しか取れず、ラウンドごとに先手が交代する。全航路に公開の基本報酬があり、自分だけが知る依頼は、合う航路を取ったときに公開してボーナスを得るか、手札に残せる。両者が同じ候補から同数を秘密に選ぶので配布の強弱は生じない。取り方と公開済みの依頼が、まだ何を持っているかの手掛かりになる。少数ラウンドから試す。航路3枠を固定し、需要の持ち越しは比較する改稿案として扱う。

次は最後のラウンドの計算例。二人は同点で、先手Aの依頼は使用済み。この例では近距離・遠距離の公開報酬を、Aは3点・2点、後手Bは1点・2点と置く。Bの残った依頼は近距離か遠距離に一致すると2点を足す。残りの枠は0点なので、Bは空いている方の航路を取る。各セルはこのラウンドの **A得点 − B得点** を表す。

| Aの手 | Bの依頼は近距離 | Bの依頼は遠距離 |
| --- | ---: | ---: |
| 近距離を取る | ＋1（3 − 2） | −1（3 − 4） |
| 遠距離を取る | −1（2 − 3） | ＋1（2 − 1） |

Bが以前に公開報酬の低い遠距離枠を優先したなどの理由で遠距離依頼を強く疑うなら、Aは自分の公開得点を1点譲って遠距離を塞ぐ。消費済みの依頼や過去の傾向から近距離が本命だと読むなら、近距離を取る。こうして**同じ公開盤面で相手の意図の仮説を変えたとき、合理的な手が逆転する**。この盤面は評価機の動作を確認する手計算例。実ゲームで報酬差を作る方法と、この盤面への到達可能性は未検証。履歴から本当に推測できるか、同様の局面が試合中に何度現れるかは試遊で調べる。

乱数の初期案はゼロとし、比較版では対戦開始前に公開する航路需要を小幅に振る。変動で有力な手が増えるか、単に有利な席が変わるかを確かめる。操作を決めてからの抽選は初期案から省く。秘密は意図を読む材料、公開乱数は対戦ごとの条件の違いとして、それぞれ効きを測れる。

## AIは人間と同じ席から考える

ゲームエンジンが初期化、手の適用、終局、勝敗、全状態を管理する。対戦エージェントと人間UIは同じ観測インターフェースから、公開盤面、公開履歴、自分の手札、自分の合法手IDを受け取る。AIは合法手IDを返し、ゲームエンジンが処理する。伏せ札が報酬だけを変える設計なら、公開枠の選択可否から相手の秘密が漏れにくい。相手の伏せ札だけが異なり、自席からは区別できない二つの到達可能な局面を用意し、AI入力・画面表示・合法手IDと順序が一致することを検査する。方策が使う乱数も固定すれば、選ぶ手まで照合できる。ゲームseed、真の伏せ札を使った診断、完全なリプレイは監査側に置く。 [OpenSpiel Core API Reference](https://openspiel.readthedocs.io/en/latest/api_reference.html)

人間用の対戦相手は、まず自己利得を優先する方策と、相手が次に取りたい枠を履歴から推測する方策で作る。次の強度を足すなら、自席の観測に整合する秘密と相手の応答を想定し、一定の試行数で先読みする。試行数の違いが実際の難度差になるかは交差対戦で測る。完全情報のゲームでも探索予算が小さければ強さは変えられ、部分観測を入れても推定が強ければAIは強くなる。見分けられない秘密ごとに真の状態を解き、毎回その正解を使えると仮定すると、実戦で使えない判断を評価してしまう。 [Cowling ほか、情報集合モンテカルロ木探索](https://eprints.whiterose.ac.uk/id/eprint/75048/1/CowlingPowleyWhitehouse2012.pdf)・[Goodman ほか、ボードゲームの技能差の測定](https://tabletopgames.ai/assets/pdf/Goodman2024SkillAnalysis.pdf)

## 自動試遊は欠陥を見つけ、判断が変わった対局を残す

GAVEL は実行できるルール表現を用い、安いランダム対戦と探索を用いた対戦で候補を絞り、上位作を専門家が試遊した。ボードゲーム開発の事例研究では、AIが特定の初手への集中や、勝つために終局を妨げる手を発見した一方、アイコンや手番進行の混乱は人間の試遊が見つけた。今回も、計算で確認できる条件と、初見の人が説明できる判断を段階的に確かめる。 [GAVEL §4.3・§6.2・§7](https://arxiv.org/html/2407.09388)・[Goodman ほか、AI試遊を用いた開発事例](https://tabletopgames.ai/assets/pdf/goodman2023casestudy.pdf)

| 評価 | 実行する比較 | 残す証拠 |
| --- | --- | --- |
| **成立・情報漏えい** | 型、合法手、資源、終局、席別観測、リプレイを照合する。末尾など小さい部分は全列挙する。 | 最短の失敗リプレイ。規則による引き分けと、異常な手数上限での打ち切りは別記する。 |
| **席差・定石・技能差** | ランダム、目先の利益、相手読み、探索を席交換して交差対戦する。頻出の初手は固定・禁止し、対策する方策とも当てる。 | 方策ペアごとの勝点率と席差。初手がどの相手にも通るのか、対応できるのかが分かる局面。 [Jaffe ほか、方策を制約するバランス評価](https://grail.cs.washington.edu/wp-content/uploads/2015/08/jaffe2012ecg.pdf) |
| **読み合い** | 自席の観測に整合する秘密を使い、同じ局面から候補手をそれぞれ試す。対戦相手を早取り型・温存型などに替え、手の期待勝点の順位が逆転するか調べる。さらに、枠の占有を外す版、依頼を全公開する版、依頼を無効にする版で、どの仕組みが判断を生んだか比較する。 | 逆転の頻度、差と不確かさ、公開の兆候・選択・帰結がそろう手番。勝ちを1、引き分けを0.5、負けを0として比較し、点差は説明用に残す。 |
| **乱数の影響** | 公開初期値のseedと方策seedを分ける。同じ初期値で席を交換し、方策seedは複数試す。公開初期値だけを変える比較では、方策を再実行して勝敗や引き分けの反転を数え、方策を一段強くした差と並べる。 | 初期値別・ペア別の勝点率、結果が変わった対局の割合。区間推定では席交換した対局を一組にし、同じ公開条件の反復もまとめる。少数の公開条件なら全列挙して出現確率で集約する。 [Goodman ほか、ボードゲームの乱数の測定](https://tabletopgames.ai/assets/pdf/Goodman2024RandomAnalysis.pdf) |

評価機にも対照が要る。公平な抽選だけで勝つものは席差を通っても手の影響で落ちるべきで、自分の点だけを積む競争は探索がランダムに勝っても相手への適応で落ちるべきだ。固定した一手で毎回勝てる候補は初手の検査で捕まえる。これらと「灯台群」の計算例を先に揃えると、評価機が狙った問題を区別できる。手数やAIの応答時間も記録し、先手差・読み合い・乱数・テンポの許容値は試作データから決める。

## 改稿は点数より、消えた選択肢を直す

ABA Games は、操作や制作基盤を絞って案を量産し、単調な入力と探索で得た入力を比較して、技能が報われるかを調べた。別の制作実験では、静止の有利さを検出した後、自動改稿が操作を続けないプレイヤーへの罰則に走り、反復工程を廃止した。このファクトリーで「買い占めが有利」と出たら、作者に集計値と問題局面を返し、枠の価値・費用・期限のうち一つを変えたとき、どの状態で別の選択が合理的になるかを答えさせる。 [制約からミニゲームを作る方法](https://aba.hatenablog.com/entry/2023/09/14/210838)・[探索入力と単調入力の比較](https://aba.hatenablog.com/entry/2026/01/19/180252)・[自動改稿を見直した記録](https://aba.hatenablog.com/entry/2026/03/11/182225)

作者が出力するのは、形式を固定したルールデータと「どの状況でどの判断を生みたいか」という仮説。まず共有枠、報酬、依頼、手番順、終了条件を型で表し、同じ定義からエンジンと説明文に必要な情報を得る。「お題がルールを変えた」と言える候補には、その題材固有の制約と、それによって実際に手が変わる局面を添える。各稿にはルール、エンジンと方策の版、seed、評価の内訳、再現用の手順を保存する。前稿と同じ条件で変更の効果を測り、そのあと未使用のseedと方策で確認する。予算内に条件を満たした稿を人間試遊へ送り、尽きたときは反例を残して保留する。既存の生成・検査・独立レビュー・改稿の工程と、TRPG版の席ごとの観測がこの土台になる。 [汎用ファクトリー](../templates/factory/README.md)・[TRPGの席ごとの観測](../templates/trpg/human.mts)

初見の人には候補と対照を同じ体裁で渡し、順番や先後を入れ替える。ルールを読み始めてから初手までと、終了までの時間を測る。試遊後に「相手の何を見て手を変えたか」「次はどの手を試したいか」を聞き、手番ログと結び付ける。再戦できるときは実際の選択も記録する。評価機の校正に使ったゲームと別のデザインを取り置き、同じデザインの別seedによる再評価に加えて、人間の選好と指標の一致を確認する。少人数の段階では、割合を一般化せず、手が変わった理由や混乱した箇所を集める。

## 最初に検証する仮説

「灯台群」と公開版・占有なし版・初期値に小幅な乱数を加えた版を並べる。共有枠が先回りを生み、伏せ札が相手の履歴を見る理由を足し、初期値の揺れがその判断を残したまま展開を変える、という順で仮説を確かめる。最初の成功条件は、機械が拾った判断の分岐を、人間も自分で見つけて説明できること。試作の勝率、乱数の許容範囲、AIの難度、再戦希望は現時点で未測定。
