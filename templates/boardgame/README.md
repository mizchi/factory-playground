# 対戦ボードゲームのファクトリー

お題から形式ごとの短い2人対戦を作り、LLMで試遊する。Viteの試遊室で、生成時と同じルールを使って人間がCPU、CLIエージェント、Jevと対戦できる。

## お題から作る

```sh
just boardgame '霧の街で通信帯域を奪い合う'
just boardgame '閉場前の夜市で売り時を競う' invest 2 23
```

第2引数は `all`（既定）、`claim`、`duel`、`invest`、`auction`、`mine`、`islands`、`resonance`。第3引数は形式ごとの最大稿数、第4引数は初期条件のseed。既定の実行では7つの形式それぞれに案を作る。作者は題材に沿った名前・数値・長さ・判断の仮説をJSONで出力する。ブラウザと自動対戦で同じエンジンを使う。

| 形式 | 駆け引き | 機械検査が拾う局面 |
| --- | --- | --- |
| `claim` 共有枠の先取り | 得意枠で稼ぐか、相手の選択肢を減らすか。6ラウンド以上では見送った枠に点がたまる。 | 自分の即時点を譲る一手で、相手の取れる最高点が下がる。 |
| `duel` 伏せた手の同時公開 | 今の勝ちを取るか、限りのある札を後に残すか。4ラウンド以上では各手を2枚ずつ持つ。 | 公開履歴のあるラウンドで、選択肢を持つ席の手が、相手の残り手によって勝ち・負け・引き分けに変わる。 |
| `invest` 投資と得点の競争 | 先に払うと将来の収入が増える。換金は各ラウンド先着一人で、自分だけに見える得意な時期がある。 | 投資した手番を資金獲得に置き換えると、実際に選んだ換金の費用に届かない。 |
| `auction` 封印入札 | 今の品に入札するか、後の品に資金を残すか。公開後は双方が入札額を支払う。 | 相手と同額なら流れる品を、大口で取り切る。 |
| `mine` 採掘と撤退 | 相手の掘り方で変わる落盤の危険を読み、もう掘るか帰るか選ぶ。 | 帰還した側の鉱石が得点になり、掘り続けた側の鉱石が落盤で失われる。 |
| `islands` 群島の産業と交易 | 1ラウンドに2手。共有施設を取って資源を集め、設備・出荷・秘密の委託へ配分する。 | 造船所を建て、解禁した外洋便で得点する。 |
| `resonance` 送電と連鎖 | 共有の回路で、今取る点・増幅の残り回数・相手に渡す充電を比べる。 | 入口から二つの塔まで連鎖させて追加点を得る。 |

まず双方の先手で合法手を探索し、狙った局面に到達できる手順を `potential.json` に残す。その局面が存在する稿について、先手を替えて2対局する。各LLMには自席の観測と合法手だけを渡し、その時点の選択理由を残す。合法手が一つの箇所は自動で進める。機械検査で拾った候補を独立した編集者のLLMが読み、理由が盤面と食い違ったり、狙った効果の根拠がなければ改稿する。作者が説明文に規則を足しても、実際のルールは型で定義された数値と固定エンジンから決まる。

`runs/boardgame-*/<形式>/draft-N/` に `rules.json`、先手が異なる `match-1.json` と `match-2.json`、`assessment.json` を保存する。試遊ログには各手番の席から見えた情報と理由が入るので、両席の秘密を含む。人間への配布には `rules.json` を使う。段階は以下の通り。

- `READY_FOR_HUMAN` は機械の候補局面を編集者が根拠として認めた状態。形式フォルダー直下にも `rules.json` を出力する。
- `NEEDS_EDIT` は上限までに根拠が揃わなかった状態。試したい稿は `draft-N/rules.json` から開ける。
- `ERROR` はモデル呼び出しなどが中断した状態。残った途中ログと `result.json` から原因を確認できる。

試遊数が少ないため、勝率や面白さの判定は人間試遊で確かめる。乱数の `variation` を使う案も、全ラウンドの加点を初手前に公開し、加点は1点まで。先取り型と投資型の秘密の得意条件は初期seedから配られる。先取り型では同じ得意枠を配らない。手を決めるとルールに従って結果が確定する。

既定の作者・両席・編集者は、既存ファクトリーと同じ認証済みの `codex` を使う。役割ごとに `BOARDGAME_AUTHOR_AGENT`、`BOARDGAME_PLAYER1_AGENT`、`BOARDGAME_PLAYER2_AGENT`、`BOARDGAME_REVIEWER_AGENT` で `codex` / `claude` / `pi` を選べる。それぞれ末尾を `_MODEL` にした環境変数でモデル名を指定できる。

## Jevを対戦席にする

```sh
source ~/.profile
export TYPESAFE_API_KEY
BOARDGAME_PLAYER1_AGENT=jev BOARDGAME_PLAYER2_AGENT=jev just boardgame '霧の街の港を取り合う' claim
```

片方だけを指定すると、その席だけJevになる。作者と編集者はCLIエージェントを使う。Jevには自席の情報と合法手を [TypeSafeのChoice](https://docs.typesafe.ai/primitives/choice) で渡す。試遊ログには返されたモデル名・確信度・手ごとの確率が入り、理由欄は空になる。モデルの既定は `jev-latest`。`BOARDGAME_JEV_MODEL` で変更でき、自動試遊では席ごとの `_MODEL` が優先される。

## 人間が対戦する

```sh
pnpm --dir templates/boardgame install --frozen-lockfile
just boardgame-web
```

起動時に表示されるローカルURLを開く。同梱の7サンプルを選ぶか、右上の「ルールJSONを開く」で生成稿を読み込む。「対戦相手」で即応するCPU、LLM、Jevを切り替えられる。Jevを選ぶ場合は、上と同じように `~/.profile` を読み込み、`TYPESAFE_API_KEY` をエクスポートしてからViteを起動する。キーはViteサーバーの環境変数から読み込む。LLMとJevは、ローカルAPIが組み立てた席2の観測で応手する。`pnpm --dir templates/boardgame build` で静的配布する場合はCPUで試遊できる。手元での試遊用なので、ブラウザはゲーム進行のために秘密も内部状態として保持する。

同梱の「灯台群」「霧の決闘」「夜市の行商」はそれぞれ8・6・8ラウンド。「遺物市の封印入札」は9ラウンド、「赤穴坑道」は8ラウンド。盤面では、その手番で比べられる判断を先に示す。「手を比べる」を開くと、得点、相性、投資で増える残り収入を合法手ごとに確認できる。選ぶと得点、枠の締切、伏せ札の公開、設備と収入の増減が盤面に出る。終局後は「相手を見て変えた手」を記入し、行動・公開ログ・感想をJSONで保存できる。

`just boardgame-test` で終了、席別観測、証拠局面、再生を検査する。背景は[設計と評価の調査](../../reports/対戦ボードゲーム%20設計と評価.md)に記載。


### 三卓巡り

「三卓巡り」または `?mode=run&opponent=jev` から開始する。毎ステージ、7形式から引いた3卓に対し、相手の先行点、勝利でもらえる巡回点、敗北時に失うライフを表示する。ライフ3で5卓を踏破する連戦で、巡回点3を使うと卓と卓の間でライフを1回復できる。引き分けはライフも巡回点も動かない。直前と同じ形式は次の候補に出ない。進行と対局中の手は同じブラウザに保存される。


### 潮路諸島

`?game=islands&opponent=jev` で直接開く。8ラウンドで各プレイヤー16手。設備の生産は次のラウンドから始まる。近海便は少ない資材で出せ、外洋便は造船所を建ててから使える。潮によって得点と積荷が変わり、同じ出荷枠に両方が出すことはできない。終局時は指定の設備と出荷2回が揃えば秘密の委託分を加点する。新しく始める三卓巡りにも出現する。


### 雷奏回廊

`?game=resonance&opponent=jev` で直接開く。見通しを盤面から追えるように、回路は入口・中継器・得点塔の3段。入口ごとのボタンに即時点と相手に残る最大得点を表示する。「経路を下見」を押してから手を選ぶと、送電前に光が通る経路を確認できる。第2・3・6・7ラウンドの開始時には、中継器と塔が放電の一歩手前まで充電される。各自2回の増幅をそこに残すか、早めに使うかが判断になる。

実際の送電では、計算した伝播経路を順に発光させる。塔の放電で得点を表示し、その後に得点表を更新する。端末が動きを減らす設定の場合は、盤面と得点を直接更新する。
